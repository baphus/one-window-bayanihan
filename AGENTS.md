## Commands and verification

- Install locked dependencies with `composer install` and `npm ci`. Use npm / `package-lock.json`; `.npmrc` disables lifecycle scripts (`ignore-scripts=true`).
- `composer run setup` copies `.env` only if absent, but always generates an app key and runs `migrate --force` before installing/building JS. Use only for initial bootstrap after configuring database access; not as a harmless dependency refresh.
- `composer run dev` starts Laravel, queue listener for **both** `default,notifications` (`--tries=3 --timeout=0`), and Vite. `npm run dev` starts only Vite at `127.0.0.1:5173`. No Pail process: Windows lacks `pcntl`.
- PHP suite: `composer run test` clears config before `php artisan test`. Focused: `php artisan config:clear`, then `php artisan test --compact tests/Feature/NameTest.php` or `php artisan test --compact --filter=test_name`.
- Frontend: `npm run test:run` is one-shot; `npm test` watches. Focused: `npm run test:run -- resources/js/Hooks/__tests__/useUnsavedChanges.test.jsx`.
- Frontend changes: `npm run typecheck` and `npm run build` are separate checks. Vitest alone does not verify production bundling.
- PHP changes: run `vendor/bin/pint --dirty --format agent`; CI checks `vendor/bin/pint --test`. Read `testing-best-practices` skill before adding tests; PHPUnit, not Pest.
- CI security gates include `composer audit`, `node scripts/npm-audit-filter.mjs`, and Ward with `.ward-baseline.json`. Raw `npm audit` does not reproduce the filtered gate.
- Docker stack: `docker compose up -d`; explicit migration runner: `docker compose --profile migrate run migrate`.

## Database and environment traps

- PHP database tests need a dedicated PostgreSQL `bayanihan_test` database and valid connection credentials; `phpunit.xml` sets `DB_SSLMODE=disable`. Reports use PostgreSQL-specific SQL; SQLite is not a substitute.
- Fresh database creation / `RefreshDatabase` loads `database/schema/pgsql-schema.sql` before remaining migrations. Keep `psql` on `PATH`, including in environments that migrate on boot. CI installs the client explicitly.
- The schema dump was generated by PostgreSQL 18.2 and contains `\restrict` and `SET transaction_timeout`; check client/server compatibility when schema loading fails. Migration files alone are not the full baseline. `RlsMigrationIntegrityTest` also checks dump text, so regenerate deliberately and run that test.
- `phpunit.xml` replaces cache/session with array, queue with sync, and supplies fake canonical `STORAGE_*` credentials. File-storage tests use the `object-storage` disk; follow neighboring tests' fakes.
- CI uses PostgreSQL 17; local Compose uses PostgreSQL 15. Diagnose schema compatibility against the actual target, not README's version alone.
- Avoid `optimize:clear` when Redis is unavailable: it also clears the configured cache store. Use targeted `config:clear`, `route:clear`, `view:clear`, `event:clear` when undoing cache compilation.
- Production boot requires config/route/view/event caching to succeed. Config callbacks must be serializable callables, not closures (see `config/sentry.php`).

## Wiring and behavior to preserve

- Middleware, exception rendering, and routing are wired in `bootstrap/app.php`, not `app/Http/Kernel.php`. `routes/web.php` also owns session-authenticated `api/*` endpoints; inspect route middleware before moving an API-looking URL.
- Login in `routes/auth.php` is email + password followed by TOTP/recovery MFA, not email OTP. `User::isInMfaEnforcedRole()` covers every nonempty role in production, including OFW; config flags do not exempt production users.
- `/up` is shallow liveness. `/api/readyz` checks database, scheduler heartbeat and queue health and requires a monitoring token. Preserve the distinction.
- Controllers delegate business logic to `app/Services/*`; validation belongs in `app/Http/Requests/*`. Most models use `UsesUuid`; inspect the model instead of assuming integer IDs or that every model uses UUIDs.
- `SoftDeleteFlag` wraps Laravel `SoftDeletes` and maintains `is_deleted` / `deleted_by`; `CascadeSoftDeletes` also controls child restore behavior. Preserve these semantics rather than replacing them with plain deletes.
- Audit entries come from service calls and model observers configured in `config/audit.php`; check both before adding logging to avoid duplicates. Read `docs/AUDIT_STRATEGY_v2.2.0.md` before changing archive/prune behavior.
- SPA entry is `resources/js/app.tsx`, resolving `Pages/**/*.{jsx,tsx}`. Use existing `.jsx` default-export conventions unless the area already uses `.tsx`; `@/` maps to `resources/js` in Vite, Vitest and TypeScript.
- Frontend state is Inertia props + local React state. Use Inertia `useForm`, `Link`/`router`, and Ziggy `route()`; styling uses Tailwind utilities and tokens in `tailwind.config.js`.
- Form pages use `useUnsavedChanges(dirty)` and render its returned `UnsavedModal`. Inertia's `before` event exposes `event.detail.visit`, not `event.visit`.
- Redirect flashes auto-toast via `FlashMessageWatcher` in `ToastProvider.jsx`; preserve repeated messages across navigation instead of adding persistent dedupe state.
- Preserve Vite's pre-resolve `util` / `node:util` stub plugin: ordinary aliases run too late for Rolldown's Node built-in handling. Vitest does not exercise this production-build path.
