# MFA login challenge (phase 1)

There is no `MFA_LOGIN_CHALLENGE_ENABLED` flag in the codebase. The challenge runs whenever the verified candidate has `mfa_enabled_at` set and `User::isInMfaEnforcedRole()` returns true (`app/Http/Requests/Auth/LoginRequest.php:76`, `app/Models/User.php:118-131`); in production that helper returns true for every role, so every enrolled user is challenged. Enrollment is enforced separately by `CheckMfaEnrolled` through `MFA_ENROLLMENT_ENFORCEMENT_ENABLED` and `MFA_ENROLLMENT_ENFORCED_ROLES` (`config/mfa.php`, `app/Http/Middleware/CheckMfaEnrolled.php`). Challenge tuning is `MFA_LOGIN_CHALLENGE_TTL`, `MFA_LOGIN_CHALLENGE_MAX_ATTEMPTS`, `MFA_LOGIN_CHALLENGE_WINDOW`, and `MFA_LOGIN_CHALLENGE_REPLAY_TTL` — also config keys, not feature flags. The password POST does not authenticate the user; it stores a pending challenge and redirects to `GET /login/mfa` (`app/Http/Controllers/Auth/AuthenticatedSessionController.php:36-44`).

The challenge page (`resources/js/Pages/Auth/MfaChallenge.jsx`) submits `code` to either `POST /login/mfa/totp` or `POST /login/mfa/recovery`, or `POST /login/mfa/cancel`. Successful requests redirect to the original intended URL (and retain the login `remember` choice) (`app/Http/Controllers/Auth/MfaChallengeController.php:70-84`). Failed requests return normal Laravel validation errors (422 for JSON clients). The show endpoint returns `{expires_in}` for JSON clients and otherwise renders `Auth/MfaChallenge` (`app/Http/Controllers/Auth/MfaChallengeController.php:20-26`).

Recovery codes are only returned by the enrollment and explicit password-confirmed regeneration endpoints. Recovery-code retrieval is not a GET operation.
